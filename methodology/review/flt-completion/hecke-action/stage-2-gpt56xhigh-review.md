## Adjudication

1. **A genuine `T₀`-valued `GaloisRep` is not justified at this boundary.**

   `GaloisRep.IsAutomorphicOfLevel` consumes an already constructed representation; it constructs none. The live `FLT-AUT-GALOIS` design remains an explicit **OBSTRUCTION**, with attachment, coefficient transport, and local-global compatibility absent ([AUT-GALOIS report](/Volumes/second-store/devel/proof-forks/FLT/methodology/review/flt-completion/automorphic-galois/stage-1-opus48-primary.md:65)).

   Stage 1’s `residually_irreducible` is also only `GaloisRep.IsIrreducible`, whereas the deformation API requires `Representation.IsAbsolutelyIrreducible`. It is not tied to the maximal ideal or a selected residual model.

   The honest order is:

   ```text
   Hecke-valued determinant/pseudorepresentation
     → residual absolute-irreducibility theorem
     → explicit reconstruction theorem
     → genuine framed S-good GaloisRep over T₀
   ```

   The pin has no pseudorepresentation/determinant-law API and the source register has no exact reconstruction source. Broad SRC-008/SRC-009 citations cannot fill that theorem. Therefore C2 is rejected, not merely deferred.

2. **C1 does not establish the claimed finite complete-local factor.**

   Temporary probes found:

   - `IsLocalRing (Localization.AtPrime 𝔪)`: green.
   - `IsNoetherianRing (Localization.AtPrime 𝔪)`: green.
   - localized-module finiteness: red until a finite-over-Hecke instance and `Localization.Finiteness` import are supplied.
   - `Module.Finite 𝓞 (Localization.AtPrime 𝔪)`: red.
   - `TopologicalSpace`, `IsTopologicalRing`, `CompactSpace`, `IsAdicTopology`, and `IsAdicComplete` for that localization: all red.

   The mathematical “finite product of complete local factors” argument needs a Henselian/idempotent-factor theorem and coefficient-residue ownership. It is not an inference from the current pin. `ResidueCharP` alone does not say that `T₀` has the same residue field as `𝓞`, which `ProartinianCat 𝓞` requires.

   The current deformation API additionally requires `[Finite (ResidueField 𝓞)]`, `[IsAdicComplete (maximalIdeal 𝓞) 𝓞]`, even degree, `3 < p`, an absolutely irreducible framed residual representation, and an actual functor membership witness ([Representable.lean](/Volumes/second-store/devel/proof-forks/FLT/FLT/Deformations/Representable.lean:53)). C1/C3 omit these.

3. **The Frobenius normalization is over-generalized.**

   Arithmetic Frobenius and `det = Nv` are correct in the live predicate. But that predicate uses:

   - the `ℤ_[p]` Hecke algebra;
   - `Q = ∅`;
   - trivial `χS`;
   - `ContinuousSMul ℤ_[p] A`.

   See the exact definition in [Automorphic.lean](/Volumes/second-store/devel/proof-forks/FLT/FLT/GaloisRepresentation/Automorphic.lean:70).

   Stage 1 silently changes all three relevant boundaries to arbitrary `𝓞`, arbitrary `Q`, and arbitrary `U₁Data.χS`. No Hecke coefficient-change theorem or nebentypus/determinant bridge exists. Thus neither its trace field nor `det = Nv` follows from `IsAutomorphicOfLevel`.

   Its `unramified` field is also ill-typed:

   ```lean
   (p : 𝓞) ∉ 𝒮.S ∪ 𝒮.Q
   ```

   Probe errors included `Membership 𝓞 (Finset (HeightOneSpectrum ...))`. The intended condition is on `v`:

   ```lean
   ∀ v, ↑p ∉ v.asIdeal → v ∉ 𝒮.S → v ∉ 𝒮.Q → ρ.IsUnramifiedAt v
   ```

   C2 also lacks `[IsTopologicalRing T₀]`, required by `GaloisRep.det`, and lacks even `[IsLocalRing T₀]`, required before forming its residue field.

4. **Surjectivity is unsupported.**

   The full Hecke algebra really is generated by every good-prime `Tᵥ` and every nonzero `U_{v,α}` at `v ∈ Q`; this is the clean theorem [adjoin_T_U_eq_top](/Volumes/second-store/devel/proof-forks/FLT/FLT/AutomorphicForm/QuaternionAlgebra/HeckeOperators/Concrete.lean:939). The anemic algebra contains only the `T` generators.

   Stage 1 supplies only `trace_frob` for `T`. It has no field hitting any `U_{v,α}`. Moreover, `RtoT` is typed as a bare `RingHom`, losing the coefficient-algebra property needed to capture scalar generators.

   The exact probe-green criterion is:

   ```lean
   theorem surjective_of_hits_hecke_generators
       {R T₀ : Type*} [CommRing R] [Algebra 𝓞 R]
       [CommRing T₀] [Algebra 𝓞 T₀]
       (φ : R →ₐ[𝓞] T₀)
       (ι : HeckeAlgebra D 𝒮 →ₐ[𝓞] T₀)
       (hι : Function.Surjective ι)
       (hT : ∀ v (hvS : v ∉ 𝒮.S) (hvQ : v ∉ 𝒮.Q),
         ∃ r, φ r = ι (HeckeAlgebra.T D 𝒮 v hvS hvQ))
       (hU : ∀ v (hvQ : v ∈ 𝒮.Q) a (ha : a ≠ 0),
         ∃ r, φ r = ι (HeckeAlgebra.U D 𝒮 v hvQ a)) :
       Function.Surjective φ
   ```

   This was proved temporarily from `adjoin_T_U_eq_top` with exactly the standard axiom trio. Stage 1 has `hT` only; its first mathematical surjectivity residual is precisely `hU`.

5. **`(RtoT, smul_compat)` does not by itself instantiate `ker_RtoT_le_nilradical`.**

   The final two arguments do have the expected shape, but the theorem also requires the entire patching environment: the families `R i`, `M i`, ultrafilter, quotient identifications, compatibility, uniform bounds, patching system, topological hypotheses, and `Module R₀ M₀`/scalar-tower instances ([REqualsT.lean](/Volumes/second-store/devel/proof-forks/FLT/FLT/Patching/REqualsT.lean:23)).

   C4 does not explicitly supply `Module R M₀`, `Module 𝓞 M₀`, or `IsScalarTower 𝓞 R M₀`. Its `smul_compat` therefore is not an exact elaborated field as written.

   C5’s freeness assertion is aimed at the wrong module: `ker_RtoT_le_nilradical` requires freeness and uniform rank for every patched `M i`, not freeness of `M₀` ([REqualsT.lean](/Volumes/second-store/devel/proof-forks/FLT/FLT/Patching/REqualsT.lean:45)). The theorem internally derives finiteness of `M₀`.

   The adapter applying `ker_RtoT_le_nilradical` belongs in `FLT-PATCHING`, where all ambient hypotheses exist. Putting it in `Hecke.lean` would reverse the intended implementation dependency.

6. **The classifying map uses the wrong interface.**

   `isUniv : Prop` is not a universal property, and an arbitrary unframed rank-two `GaloisRep` is not an element of the live framed deformation functor. The exact generic map already available from category theory is:

   ```lean
   noncomputable def deformationClassifyingMap
       {𝓞 : Type u} [CommRing 𝓞]
       {F : Deformation.ProartinianCat 𝓞 ⥤ Type u}
       {R T : Deformation.ProartinianCat 𝓞}
       (isUniv : F.CorepresentableBy R)
       (Δ : F.obj T) : R ⟶ T :=
     isUniv.homEquiv.symm Δ
   ```

   This probe is standard-trio clean. The missing mathematics is constructing the exact S-good functor, proving its corepresentability, and producing `Δ : F.obj T₀` from the reconstructed Hecke-valued representation.

7. **The proposed public axioms are rejected.**

   Neither

   ```lean
   axiom exists_attachedLocalGaloisRep
   axiom heckeModuleLoc_free
   ```

   is acceptable. Nor are placeholder hypotheses such as `hEis : Prop` or `isUniv : Prop`. They must remain named provider obligations:

   - `FLT-HECKE-LOCAL-FACTOR`;
   - `FLT-HECKE-PSEUDOREP`;
   - `FLT-HECKE-RECONSTRUCTION`;
   - `FLT-HECKE-MULTIPLICITY-ONE`;
   - `FLT-HECKE-TU-COMPAT`;
   - existing `FLT-DEF-FUNCTOR`, `FLT-SGOOD-SELECTED`, and `FLT-TW-PRIMES`.

8. **Dependency orientation needs repair.**

   The current graph correctly has `FLT-SGOOD-SELECTED → FLT-DEF-FUNCTOR`, `FLT-HECKE-ACTION → FLT-PATCHING`, and `FLT-TW-PRIMES → FLT-PATCHING` ([proof graph](/Volumes/second-store/devel/proof-forks/FLT/methodology/control/proof-graph.ndjson:59)).

   It is missing the direct edge:

   ```text
   FLT-DEF-FUNCTOR → FLT-HECKE-ACTION
   ```

   Calling this “transitive” is incorrect: `SGOOD` is a common predecessor, not a path from `DEF-FUNCTOR` to `HECKE-ACTION`.

   The transitively reduced repaired route is:

   ```text
   FLT-AUT-GALOIS
        → FLT-HECKE-PSEUDOREP
        → FLT-HECKE-RECONSTRUCTION
        → FLT-HECKE-DEFORMATION-POINT

   FLT-SGOOD-SELECTED
        ├→ FLT-DEF-FUNCTOR
        └→ FLT-HECKE-DEFORMATION-POINT

   FLT-HECKE-LOCAL-FACTOR ─┐
   FLT-DEF-FUNCTOR ─────────┼→ FLT-HECKE-CLASSIFYING-MAP
   FLT-HECKE-DEFORMATION-POINT ┘
        → FLT-HECKE-TU-COMPAT
        → FLT-HECKE-ACTION
        → FLT-PATCHING

   FLT-LOCAL-GALOIS → FLT-TW-PRIMES → FLT-PATCHING
   ```

   `FLT-TW-PRIMES` stays a sibling provider for patching; it is not made an upstream dependency of the generic Hecke factor.
